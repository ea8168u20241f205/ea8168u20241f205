## Stack

JavaScript, Vue 3.5.44+, Vite, Composition API, PrimeVue 4.5.5 and PrimeUIX Themes 2.0.3 (MIT-licensed Material preset), PrimeFlex, PrimeIcons, Vue Router, Vue I18n, Pinia, Axios and JSON Server 0.17.4. Requires Node.js 22.12+ or Node.js 24 LTS.

## Setup

```bash
npm ci
npm run server
```

In a second terminal:

```bash
npm run dev
```

Open the URL printed by Vite. Run `npm test` for business rule tests and `npm run build` for the production build. `npm run preview` serves the build locally; the API must remain running.

## Environment configuration

The included development and production environment files define both API URLs, endpoint paths and the Logo.dev provider. For the required logo, create `.env.development.local` and set `VITE_LOGO_API_KEY` to your own Logo.dev **publishable** token. Never put a secret API key in a Vite variable. `VITE_LOGO_DOMAIN=astararetail.pe` identifies the brand. Without a token, the toolbar displays a textual Astara badge; this fallback does not satisfy the Logo.dev logo requirement. Configure `.env.production.local` and real API URLs for deployment. Restart Vite after changing environment variables.

## Architecture

- `shared`: base API and endpoint, layout, language selector, Home and unknown route views.
- `showroom`: section and inventory entities, capacity policy, assemblers, local API, Pinia store, summary cards and creation view.
- `vehicles`: external catalog entity, assembler, API and independent Pinia store.

Each bounded context separates domain, infrastructure, application and presentation as needed. Route-bound components live in `views`; reusable components live in `components`. Templates use PrimeVue `pv-` aliases and PrimeFlex utilities. The only custom CSS sets the base font family, for which PrimeFlex provides no equivalent utility; layout and spacing use PrimeFlex. JavaScript and Vue script blocks include English JSDoc attribution.

## Routes and behavior

- `/` redirects to `/home`.
- `/home` displays one card per section, vehicle names and quantities, summed totals and remaining capacity.
- `/vehicle/items/new` is a showroom child route. Select a section, then a vehicle supplied by DummyJSON for that section category, then a positive integer quantity.
- Unsupported routes display the requested path and a return-to-Home button.
- English is the default; EN/ES switches all interface labels, validation messages and document language.
- The desktop sidebar is persistent; smaller screens use a collapsible drawer with the language selector at its bottom.
- Create refreshes inventory and sections before capacity validation, posts only after validation, and returns Home only after success. Cancel makes no registration.
- IDs are generated by JSON Server; vehicle IDs/names and category are obtained from the selected catalog vehicle and section; registration time is generated at creation.
- HTTP failures and empty catalogs display translated messages. Obsolete catalog requests cannot overwrite the currently selected category.

## Supplied data and limitations

`server/db.json` is an unmodified copy of the provided file. Its initial inventory uses cosmetic product names despite the `vehicle` category. These existing labels are displayed faithfully; new entries use the actual vehicle titles from DummyJSON. The three initial totals/available capacities are 5/5, 4/4 and 0/6 respectively.

The external catalog endpoint is `/products/category/{category}`. All category products are requested with `limit=0`. No invented catalog fallback is used. Internet access is required for DummyJSON and Logo.dev.

JSON Server is a fake backend. The frontend refreshes before saving but cannot guarantee atomic capacity enforcement across simultaneous clients; production systems must enforce that constraint server-side. This exercise does not require authentication, deletion or editing.
